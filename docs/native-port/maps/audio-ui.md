# Porting map: audio-ui (`src/audio`, `src/ui`)

Native target: macOS app, Swift 6.4 + Metal, AVAudioEngine for sound, cross-play with the browser build.
Scope: 16 audio files (2,690 lines incl. JSON), 47 UI files (6,353 lines: 4,161 TS + 2,192 CSS).
Everything below was read from source; `file:line` references are to the current `main` (cbe0add).

---

## 1. Purpose and structure

### 1.1 `src/audio` — spatial audio engine (Web Audio)

One `AudioContext`, created on the first user gesture. The engine subscribes to `GameEvents` and turns
each event into one or more "voices" on a fixed pool of 44 node chains. Other systems call only the
`AudioSystem` contract (and in practice only `game.ts` does; nobody outside `src/audio` calls `play`/`playAt`).

| File | Lines | Responsibility |
|---|---|---|
| `index.ts` | 388 | `AudioEngine`: unlock on gesture, decode MP3s, per-frame listener update from the camera matrix, interior-zone reverb selection, event subscriptions, public `play`/`playAt`, onset trimming of decoded buffers (`describe`, 377-388) |
| `graph.ts` | 223 | Fixed graph: buses (effects / ambience loops / beds / interface), world gain, low-health "narrow" low-pass, ambience ducking, two crossfading convolver slots, master limiter -> trim -> soft-clip, L/R analyser tap, procedural sub-thump buffer |
| `pool.ts` | 370 | `VoicePool`: 44 persistent slots (biquad LP -> gain -> panner or stereo panner -> out, plus reverb send). Distance gain, air absorption, propagation delay, budgeted occlusion rays, HRTF assignment, loop refresh every 0.25 s, click-free stop |
| `voices.ts` | 171 | `VoiceBook`: pure slot bookkeeping. Priority stealing, per-group caps, `freeAt` fade guard, HRTF ranking (distance + recency) |
| `curves.ts` | 119 | Pure curves: `PROFILES` per sound class, `distanceGain`, `airCutoff`, `propagationDelay`, occlusion constants, `RaycastBudget`, `stepLevel`, `landingVolume` |
| `layers.ts` | 83 | Pure: gunshot layer mix (close/distant equal-power crossfade 35-130 m, tail, sub, mech, reverb send) per environment; `activeReverb` |

## 4. Cross-play-critical behaviour

**Audio is not on the wire.** Every sound is derived locally from `GameEvents`; the net layer re-emits events for
remote players. Audio RNG is `Math.random` (`index.ts:192-193,331`) and never needs to match between peers.
What must hold for audio to be correct in cross-play is that the native sim emits the *same events with the same
semantics*:

- `shotFired.local`, `shooterId`, `muzzle` (`gunfire.ts:42-50`); `weapon.loudness` (`gunfire.ts:45,126-128`); `weapon.muzzleVelocity > 360` supersonic test (`gunfire.ts:23,143`).
- `combatantHit.attackerId/targetId/fatal` drives hit/kill ticks (`gunfire.ts:224-235`) and HUD markers (`hud.ts:210-213`).
- `nearMiss.point` produced for remote shots near the local player (`gunfire.ts:136-169`).
- `botCallout.kind`, `died.victimId/killerId/weaponId/headshot`, `footstep.running/surface`, `landed.speed`, `grenadeBounced.speed/surface`.
- `voicePitch = 0.9 + (ownerId % 6) * 0.035` (`foley.ts:254-256`): a soldier's voice depends on the combatant id. Cosmetic, but it will only sound the same on both machines if combatant ids are shared by the protocol.
- Asset id scheme `snd-<key>-<layer>[-N]` and group derivation by stripping `-\d+$` (`catalog.ts:11,89-95`); weapon ids (`m4a1, mp5, m24, m249, m7, scarh`) and class fallbacks (`catalog.ts:19-34`). A new weapon added on the web needs the same id natively.

Deterministic-but-local math (port exactly so both builds *sound* the same, not for sync):
- Impulse responses: `generateImpulse(preset, sampleRate, seededRandom(hashString(preset)))` (`graph.ts:100`, `impulse.ts:61-107`), using mulberry32 + FNV-1a (`core/random.ts:2-21`). Port both with `UInt32` wrapping (`&*`, `&+`) to reproduce the same IRs. The output depends on `sampleRate` (44.1 vs 48 kHz differ).
- All constants in `curves.ts:24-39,69-72`, `layers.ts:35-46`, `grenade.ts:9-17`, `pool.ts:25-31`, `ambience.ts:16-25`, `graph.ts:17-22`, `index.ts:29-31`.

**UI constants that mirror the protocol or the sim. They have to stay equal to the web build:**

| Constant | Value | Where | Why |
|---|---|---|---|

### 5.2 Audio approach (recommendation)

Mirror the Web Audio graph **inside a custom render block** rather than as AVAudioEngine nodes:

```
AVAudioSourceNode(MixCore, stereo, engine rate)  -> mainMixer -> output
   voices(44) -> [biquad LP] -> [gain] -> equal-power / stereo pan -> bus
                         \-> send -> Convolver slots(2) -> effects
   beds -> bedFilter -> duck -> ambience ; loops -> duck
   effects + ambience -> world gain -> narrow LP -> master
   interface -> master
   master -> limiter -> trim -> soft clip
HRTF lanes(8): mono pre-pan voice signal written by MixCore into ring buffers ->
   AVAudioSourceNode x8 -> AVAudioEnvironmentNode(.HRTFHQ) -> world submix (re-enters before limiter
   by running the master chain as a custom AUAudioUnit after mainMixer)
```

Why: the engine depends on sample-accurate starts (propagation delay up to ~2 s, `curves.ts:58-61`; layer
delays 15-50 ms), `setTargetAtTime` time constants as short as 7.5 ms (`pool.ts:361`), automated per-voice
filter cutoffs, and convolution reverb. None of that is available on stock AVAudioEngine nodes. Keeping
the DSP in Swift also makes the Web Audio formulas portable and testable offline (render to buffer, compare
RMS/peak with `scripts/dev/audio-check.mjs` captures).

Simpler first milestone (acceptable if time is short): AVAudioPlayerNode pool -> AVAudioUnitEQ -> AVAudioEnvironmentNode,
`AVAudioUnitReverb` presets instead of convolution, volume tweened at frame rate. Expect clicks on steals and a
different room sound.

### 5.3 UI approach (recommendation)

- **Menus, sheets, lobby, settings, credits, first-run, pause, end, loading**: SwiftUI in an `NSHostingView`
  above the `MTKView`. They are form-heavy and need text input, focus, scrolling and accessibility. They are only shown while the
  game is not taking input, so SwiftUI's cost does not matter.
- **In-match HUD**: draw it in Metal as the last pass of the frame. It updates every frame (reticle arcs, minimap,
  health bars that follow projected positions, scope) and must not cost main-thread layout at 120 fps. SwiftUI over
  a Metal view at that rate risks frame pacing. A small text system is needed (MSDF atlas of Geist / Geist Mono, a
  few hundred glyphs).
- **Exceptions in-match**: chat input box and weapon picker as SwiftUI overlays (text editing; image + paragraph layout),
  shown only while open. The scene saturation and the dead dim go into the post-process shader.

## 6. Risks, unknowns, effort

### Risks

1. **Realtime DSP in Swift 6 strict concurrency.** The render block must not allocate, lock or touch actors. Use
   `UnsafeMutablePointer` state owned by the render thread, an SPSC ring for commands, `nonisolated(unsafe)` with care.
   This is the largest engineering risk.
2. **Convolution cost.** Two slots (one idle) x stereo x up to 144k taps. Partitioned FFT on Accelerate is fine on Apple
   silicon (well under 5% of a core), but it has to be written and tested.
3. **HRTF parity.** Chrome's HRTF (IRCAM-based) and Apple's `.HRTFHQ` sound different. Routing HRTF lanes through
   `AVAudioEnvironmentNode` and back before the master limiter makes the graph split in two. Alternatively drop the
   environment node and ship an HRIR set in the custom core (licence check needed).
4. **Stereo positional tails** (4 files) would be downmixed by the environment node; equal-power in the core keeps them stereo.
5. **Mix calibration.** `LIMITER_TRIM` and the onset trim exist because of browser behaviour (`graph.ts:20-21`,
   `index.ts:28-29`). Loudness has to be re-measured with the debug tap against `docs/audio-report.md`.
6. **MP3 decoding.** AudioToolbox priming handling differs; the onset scan covers one-shots, but the loop points in
   `sound-meta.json` assume browser decode offsets (0.3 s pre-roll). Verify the loops are seamless natively, or re-export lossless CAF/ALAC from `process-audio.mjs` for the native bundle (cheap, and recommended).
7. **Metal HUD text.** Need an MSDF/bitmap font pipeline for Geist/Geist Mono and tabular numbers; there is no DOM layout. The HUD
   also has to follow the CSS breakpoints (`hud.css:302-324`, `minimap.css:29-45`) for different window heights.
8. **Invite links.** Native has no `location.href`. The host's link must point to the deployed web URL, and native should
   register a URL scheme / universal link so that it can open `?join=` links itself. Which web origin is canonical is unknown.
9. **Event semantic drift.** Audio and HUD correctness depend on the sim port emitting the same `GameEvents` (including
   `local`, `nearMiss`, `combatantHit.fatal`). If the sim port renames or merges events, these handlers break silently.
10. **Duel minimap fairness** depends on `ctx.time`, which can drift between peers after pauses or joins. This is a web issue too;
    flag it for the net/sim owners instead of copying it blindly.
11. **Keyboard focus model.** Web spatial arrow-nav plus `data-nav-default` has to be rebuilt in SwiftUI (anchor preferences +
    `@FocusState`). macOS default focus behaviour is different, so getting it right takes some fiddling.
12. **WAAPI easing parity** (`cubic-bezier(0.2,0,0,1)`) is reproducible with `UnitCurve.bezier`, but each animation is hand-ported.

### Unknowns

- Whether the native renderer will expose a post-process hook for saturation/vignette/scope, or whether the HUD pass owns them.
- Whether `assets/sounds.json` (manifest) is shared verbatim with the native bundle or regenerated.
- Final list of NetErrorCodes once the native net layer exists (`friend.ts:51-84` must stay exhaustive).
